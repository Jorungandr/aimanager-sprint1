# 爱管理 Sprint 2 累积增量

本项目以 Sprint 1 的 E01 用户与权限增量为基线，继续实现项目协作链路：创建需求、创建任务、关联需求、指派项目成员、设置截止日，并在“待梳理—待办—进行中—已完成”看板中推进状态。Sprint 1 的邮箱密码登录、角色与权限、项目成员、权限矩阵和权限回收功能继续保留并纳入回归测试。

已对照实验一《项目规划方案》的Sprint 2切片：US-16创建任务及截止日、US-18需求拆解与任务关联、US-19负责人指派、US-22任务状态流转、US-24状态看板；本次补充US-28负责人筛选。这里表示代码功能对应关系，不代替团队现场AC验收。基线中的优先级、留言等其他Should/Could故事不在本次实现范围内。

## 运行

建议使用 Python 3.11 或更高版本（CI使用3.11），服务端使用标准库，无需安装第三方包。浏览器回归需要Node.js与Playwright。在本目录运行：

```text
python server.py
```

浏览器打开 `http://127.0.0.1:8765`。首次打开会显示初始化管理员页面；请自行设置管理员邮箱和密码。数据保存在代码目录中的 `data/aimanager.db`，会话保存在当前服务器进程内，2小时后或重启后需要重新登录。连续一分钟内同一IP失败登录5次后，暂时返回429，过期后可重试。本机多人演示共享IP，避免连续试错。

演示建议：初始化管理员 → 创建“项目经理、成员”角色 → 为项目经理勾选 `project.view`、`members.manage`、`workitems.manage` → 创建项目与账号并加入成员 → 用项目经理账号创建需求和任务、指派负责人及截止日 → 在看板中拖动任务到“进行中”和“已完成” → 用仅有 `project.view` 的成员账号验证可查看但不可新建或移动任务 → 回归演示 Sprint 1 的登录、权限隔离和成员移除。所有账号和密码均使用演示数据，不要使用真实凭证。

## 实现与边界

- 后端：Python 标准库 HTTP 服务、SQLite、PBKDF2 密码散列、随机会话令牌。
- 权限与完整性：Sprint 1 的四项权限继续保留，Sprint 2 新增项目级 `workitems.manage`；读取需求和任务要求 `project.view`，写入和看板变更要求 `workitems.manage`。任务负责人须为当前项目成员，需求须与任务同属一个项目，截止日采用 `YYYY-MM-DD`，状态只允许 `backlog`、`todo`、`doing`、`done`。
- 服务器执行权限校验，浏览器界面隐藏按钮仅用于辅助提示，不作为安全边界。
- 成员管理者只能指派不超过自己在当前项目权限的角色，也不能修改或移除权限更高的成员。角色维护者修改共享角色时，原有及新权限都必须在其已有授权上限内，不能给自己新增未持有的能力。
- 保存含管理权限的角色时自动包含`project.view`，旧数据库启动时补齐这一依赖。创建者自动成为新项目的项目内管理者，可查看项目、管理成员与需求任务；该身份不授予平台级角色管理权。创建者显示在成员列表并可被指派任务，不能通过普通成员操作移除或覆盖；所有权转移暂不支持。旧项目不猜测创建者，保留平台管理员兜底。
- 更新任务须携带读取时的`version`：缺失返回428、旧版本返回409，成功递增。拖动、状态选择和编辑窗口均遵守该约束。收到冲突时保留当前输入，请关闭弹窗、刷新数据后重新编辑，不自动覆盖别人修改。
- 需求支持编辑、归档与恢复，使用自己的`version`，与任务版本独立；归档保留历史任务关联，禁止新关联，恢复后可重新关联。需求和任务不提供永久删除入口。
- 当前为教学原型，监听本机地址；虽有登录失败限速、线程上限和请求读取超时，但不包含生产部署所需的 TLS、完整流量治理、账号找回、审计日志与跨设备会话持久化。
- 自动测试通过只能证明代码级 DoD 的一部分；团队仍须完成非作者审查、现场 AC 验收、截图/录屏和真实会议签认后，才能把故事标记为正式完成。

## 文件

- `server.py`：HTTP 路由与安全边界。
- `service.py`：用户、权限、需求与任务业务规则；`database.py`：SQLite连接、原子升级、备份与索引。
- `index.html`、`app.js`、`styles.css`：浏览器界面。
- `tests/`：业务、HTTP边界、接口契约、数据库迁移与健康检查测试；`.github/workflows/tests.yml`：推送与拉取请求触发的全量回归流水线。
- `scripts/check_database.py`：只读数据库健康检查；`docs/business-api.md`：实际接口与业务约定。

本轮保留Sprint 1及Sprint 2累积提交历史。成员成果先在功能分支开发，再集中整合到`feature/liuhaotian-business`并执行回归；团队完成非作者审查与现场验收后，再确认合入`main`。当前集成成果尚未整体合入主分支。CI通过不代替课程要求的人工验收及签认，证据由团队据实归档。

## 工作台操作

- 顶部切换项目协作、管理配置、权限验证；只有具备管理能力的账号显示管理配置。
- 右上项目选择器切换当前项目，成员管理、需求列表和新建表单可展开，避免多项目内容堆叠。
- 搜索任务标题或关联需求，按负责人或未指派筛选；列计数为筛选结果，完成进度为当前项目全部任务。
- 任务既可拖动，也可使用状态下拉框；编辑窗口可修改标题、需求关联、负责人、截止日与状态，Esc可关闭。
- 任务逾期按浏览器本地日期提示，已完成任务不标逾期。任务完成率是任务数比例，不是故事点速率或燃尽图。
- 移出项目成员时，在同一事务内清空该项目任务的负责人，保留任务；其他项目的负责人不变。
- 不创建演示默认密码，不覆盖现有数据库。浏览器验证使用隔离的临时数据库。

```text

```

Python不在PATH时，设置`PYTHON`为Python解释器路径。浏览器脚本验证创建项目与任务、编辑与状态更新、需求归档恢复、搜索与负责人筛选、409冲突输入保留及提交锁定、刷新重试、登录失效关闭弹窗及390px布局；CI自动安装浏览器并执行同一脚本。不要将自动测试通过视为非作者签认或现场验收。

已有且包含用户数据的数据库在需要相应列迁移时，会先生成`.pre-hardening.bak`或`.pre-requirements.bak`快照，同名备份不覆盖；结构、权限修正及版本标记在一个事务中提交，失败回滚。备份不等于最近一次业务数据，属于私有数据，不提交Git；停服恢复步骤见接口说明。

只读健康检查必须显式指定已有数据库文件，建议停服后对交付副本运行：

```text
python scripts/check_database.py "数据库副本路径"
```

退出码0表示未发现问题，1表示发现结构版本、完整性、外键或业务关联异常，2表示无法检查。工具不调用`Store`、不迁移、不修复，不存在的路径不会创建空库；输出只含固定类别、数量和最多100条定位编号，不含账号或任务文本。旧版数据库需由匹配程序另行升级，不在检查工具中升级。

技术债：审计日志、所有权转移、完整故事层级及生产部署不在本轮范围。服务器仍仅监听本机，使用最多16个请求线程和5秒读取超时；数据库与会话访问串行加锁，慢请求体在锁外读取。该设计用于课堂演示，不是生产并发容量承诺。HTTP仅限本机，不提供TLS；不要修改监听地址后直接对外开放。真实燃尽图、速率、至少三个AI角色过程记录及非作者审查必须另据实验过程提供，不能从任务计数自动推断。
