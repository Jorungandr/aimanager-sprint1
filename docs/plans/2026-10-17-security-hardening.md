# Sprint 2 安全与一致性修复实施计划

**Goal:** 修复审查确认的权限提升、创建者失权、编辑覆盖及运行边界问题。
**Architecture:** 保留标准库和SQLite；项目创建者有独立的项目内所有者权限，不能赋予平台权限。共享角色的修改和指派在服务端限制授权上限。任务用版本号条件更新；旧数据库备份后增量迁移。
**Tech Stack:** Python unittest、SQLite、原生JavaScript；浏览器冒烟测试作为可选开发依赖。

1. service.py、server.py及测试：覆盖角色自提权、修改共享角色提权、创建者访问、查看权限依赖；API必须传操作者，不改写既有用户角色。
2. service.py、app.js及测试：任务读取返回version，所有更新须提交读取时版本；冲突409，缺少版本428；移除成员导致的负责人变更同时递增version。
3. 校验文本、编号、日期、排序类型；意外异常统一JSON500，详细信息仅记录服务端。
4. 每服务器隔离会话，2小时过期；每IP每分钟5次失败登录限速。请求读取超时5秒，最多16个请求线程，数据库/会话操作加锁，先读取请求体再进入锁。
5. 补数据库迁移、API负例、版本冲突、过期/限速测试；自动浏览器脚本覆盖主操作流程，CI运行后端和浏览器检查。
6. 更新README与技术债，运行全量验证后直接推送main。原有未跟踪的SPRINT2_EVIDENCE.txt不修改、不提交。
