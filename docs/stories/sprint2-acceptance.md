## 二、S2-01 需求与任务创建

| 编号 | 验收条件（Given / When / Then） | 判定方式 |
| --- | --- | --- |
| AC-01-1 | 给定一个持有 `project.view` 的项目成员，当他打开项目工作区，则能读取该项目的需求列表与任务列表（HTTP 200），且只看到自己所在项目的数据。 | 接口 + 浏览器 |
| AC-01-2 | 给定一个被授予 `workitems.manage` 的成员，当他提交需求标题与说明，则需求创建成功（201），并立即出现在需求列表与任务的“关联需求”下拉中。 | 接口 + 浏览器 |
| AC-01-3 | 给定同一成员，当他创建任务并选择同一项目内的需求、指定本项目成员为负责人、填写 `YYYY-MM-DD` 格式的截止日，则任务创建成功（201），卡片出现在“待办”列并显示负责人与截止日。 | 接口 + 浏览器 |
| AC-01-4 | 给定一个只有 `project.view` 的成员，当他调用创建需求、创建任务或修改任务的接口，则服务器返回 403；界面不展示“新建需求或任务”入口。 | 接口 + 浏览器 |
| AC-01-5 | 给定一个未加入该项目的账号，当他被选为任务负责人，则创建被拒绝；当他尝试关联其他项目的需求，则返回 404 且不写入数据。 | 接口 |
| AC-01-6 | 给定非法输入——截止日不是 `YYYY-MM-DD`、状态不在 `backlog`/`todo`/`doing`/`done` 之内、请求携带未定义字段——则返回 400，且数据库不产生任何写入。 | 接口 |

验收要点：AC-01-4 必须验证服务端拒绝，而不是只看按钮是否隐藏；界面隐藏只作为可用性提示，不作为安全结论。

## 三、S2-02 任务看板流转

| 编号 | 验收条件（Given / When / Then） | 判定方式 |
| --- | --- | --- |
| AC-02-1 | 给定项目内已有任务，当打开看板，则任务按“待梳理、待办、进行中、已完成”四列展示，列标题显示当前列的可见任务数。 | 浏览器 |
| AC-02-2 | 给定一个持有 `workitems.manage` 的成员，当他拖动卡片到其他列，或使用卡片上的状态下拉框，则状态更新成功（200），卡片进入目标列，进度条与列计数同步变化。 | 浏览器 + 接口 |
| AC-02-3 | 给定一个只有 `project.view` 的成员，当他打开看板，则卡片不显示状态下拉框与“编辑”按钮；若直接调用状态更新接口，则返回 403。 | 浏览器 + 接口 |
| AC-02-4 | 给定编辑窗口读取任务时拿到的 `version`，当任务在此期间被他人修改，则保存返回 409 并提示刷新；请求缺失 `version` 时返回 428；更新成功后 `version` 递增。 | 接口 + 浏览器 |
| AC-02-5 | 给定看板工具栏，当输入关键字或选择负责人（含“未指派”）时，只显示匹配任务，列计数随筛选结果变化，完成进度仍按当前项目全部任务计算。 | 浏览器 |
| AC-02-6 | 给定 Sprint 1 的权限基线，当运行全量回归，则登录、角色矩阵、成员管理与移出后权限回收的用例全部通过，不因本轮增量而回退。 | 接口回归 |

## 四、界面验收检查点

本节对应产品与交互界面的交付范围，作为 AC 的补充检查项，不替代业务 AC。

| 编号 | 检查点 | 判定标准 |
| --- | --- | --- |
| UI-1 | 桌面布局 | 1440px 与 1280px 下看板四列同行、不重叠；角色与账号表单在顶部对齐；导航在滚动时保持可见。 |
| UI-2 | 移动适配 | 390×844 下不出现横向滚动（`document.documentElement.scrollWidth <= window.innerWidth`）；看板改为单列；主要按钮与输入框高度不小于 44px。 |
| UI-3 | 表单提示 | 每个输入项下方有说明格式、取值范围或后果的提示；必填项由浏览器原生校验拦截；提交失败时错误信息出现在表单附近，而不是只写进页面顶部提示条。 |
| UI-4 | 空状态 | 无项目、无成员、无需求、无任务（分列）、无角色、未发起权限检查六种情形，均有说明与下一步指引，不出现空白区域或只有表头的空表。 |
| UI-5 | 无障碍 | 键盘可完成登录、建角色、建项目、建任务与状态变更；跳转到主内容的链接可用；焦点样式可见。 |

## 六、建议演示顺序（约 8 分钟）

1. 初始化管理员并登录，说明账号与会话范围。
2. 创建“项目经理”角色，勾选查看项目、管理成员、管理需求任务；说明含管理权限的角色会自动包含查看项目。
3. 创建项目与演示账号，把成员加入项目并指派角色；说明创建者自动成为项目内管理者。
4. 用项目经理账号创建需求“看板管理”，再创建任务并关联该需求、指派负责人、设置截止日。
5. 在待办列看到任务卡片，确认负责人、截止日与需求标签显示正确。
6. 用只有查看权限的成员账号登录：可看到看板，但没有新建、编辑与状态控件；直接调用写接口返回 403。
7. 回到项目经理：拖拽或下拉把任务推进到“进行中”“已完成”，演示搜索与负责人筛选，以及旧窗口保存返回 409 的冲突提示。
8. 管理员移出该成员，验证其访问被拒绝，并说明被移出成员负责的任务会保留、负责人被清空。
